# Dual-mode OFDM PHY (ТЗ 003): architecture

Branch `OFDM_PHY_Z7020_DUALMODE`, continuation of `OFDM_PHY_Z7020`. One RTL datapath, two modes selected per packet:

| | MAX RANGE (MODE_ID 0) | MAX RATE (MODE_ID 1) |
|---|---|---|
| modulation | QPSK, ±9216 per axis (= 2.25 × QAM_UNIT, same mean power as 16-QAM) | 16-QAM Gray, ±4096 / ±12288 |
| LDPC | R = 1/2, N = 2160, K = 1080, 18 layers | R = 5/6, N = 2160, K = 1800, 6 layers |
| codewords per OFDM symbol | 1 (+ 20 filler bins) | 2 (+ 20 filler bins) |
| payload per symbol | 135 bytes | 450 bytes |
| PHY rate (asymptotic, 30.72 MS/s, 2192 samples / symbol) | 15.14 Mbit/s | 50.45 Mbit/s |
| LLR | soft, 6 bit, per-bin gain | soft, 6 bit, per-bin gain and MMSE threshold |
| equalizer | MMSE (ZF switchable) | MMSE (ZF switchable) |

Everything else is shared: Schmidl-Cox detector, coarse CFO, NCO, window + FFT, LTS channel estimate (now smoothed), noise / SNR estimator, MMSE post
engine, pilot / CPE / SFO tracker, fine-timing loop, bit-exact AXI-stream packet output.

## Frame and mode signalling

```
 [ sync ][ LTS ][ HEADER ][ data 0 ] ... [ data n-1 ]          (every symbol: 2048 + 144 samples)
```

The **header symbol** (`rtl/tx/phy_hdr_gen.sv`, `rtl/rx/phy_hdr_dec.sv`, golden `python/hdr_ref.py`) is one OFDM symbol of 1100 QPSK bins
that carries the 16 bit word `{MODE_ID(1), nsyms(8), rsv(3), CRC-4(4)}`. The word is repeated over all 2200 coded bits and XORed with a PN sequence
(15 bit LFSR, no spectral lines). The RX soft-combines ~137 repetitions (about 21 dB of processing gain), checks the CRC and selects QPSK / 16-QAM,
the LDPC code and the interleaver rotation for the following symbols **before the first data symbol arrives** (the symbol period is 4384 clocks, the header
decision takes ~20). If the CRC fails the receiver uses the register `MODE` (fallback). The header is always QPSK + repetition, so it is decoded
down to −6 dB (per sample) even when the payload is 16-QAM 5/6; MAX RANGE itself needs about +1 dB.

Mode switching is **per packet**: the TX samples `MODE` with the first byte of a packet; the RX takes the mode from the header. A packet cannot change mode
in the middle of its payload.

## TX

```
 bytes -> CRC/framing (axis wrapper) -> packet buffer -> scrambler -> LDPC encoder [cfg_mode: 1/2 | 5/6] -> interleaver [rot_en: 16-QAM only]
       -> mapper [QPSK | 16-QAM] --\
                                    +--> symbol FIFO -> OFDM mapper -> pilots -> (mux with preamble) -> IFFT -> scaler -> CP -> IQ
 phy_hdr_gen (header symbol) -------/
```

* `phy_ldpc_enc`: one encoder, tables for both codes in `phy_ldpc_pkg` (generated by `python/gen_ldpc_pkg.py`), 2-bit words (QPSK) or nibbles (16-QAM).
* `phy_tx_top`: `cfg_mode` latched with the first byte, `pkt_mode` for the encoder / interleaver / mapper, one extra data symbol (the header) in the frame controller.
* `phy_tx_axis_top.v`: register `0x18` = `ENABLE` (bit 0) + `MODE` (bit 1). Writing `1` selects MAX RANGE; write `3` for MAX RATE.

## RX

```
 IQ -> scale -> DC -> Schmidl-Cox -> coarse CFO -> NCO -> [WIN_DELAY = 704 samples, in front of the NCO since v0.8.0] -> window -> FFT -> bin select
   LTS : G = Y*sigma -> [3-bin smoothing] -> |G|^2, weights, log codes, fine timing          noise (guard bins) -> post engine (MMSE gain / bias per bin)
   data: equalizer -> CPE + SFO slope tracker -> LLR demapper [QPSK | 16-QAM] -> deinterleaver [rot_en] -> LDPC decoder [1/2 | 5/6] -> descrambler -> packet
   header symbol: tracker -> QPSK LLR -> phy_hdr_dec -> (MODE_ID, nsyms, CRC ok)  --> mode_q for the data symbols
```

New / changed RX blocks:

| block | change |
|---|---|
| `phy_hdr_dec` | repetition-code soft combiner + CRC-4 |
| `phy_llr_demap` | QPSK path (`qpsk` flag pipelined with the bin): `LLR = sat(((-(x + x>>3)) * gm) >> (SH_C - ge - 1))` |
| `phy_rx_decode_ldpc` | header routing, QPSK bin pairing into 4-LLR decoder words, mode-dependent codeword count |
| `phy_ldpc_dec` | two codes on one datapath (`cfg_cs`): layer count 6 / 18 (ring write index `lmb-1`), tables per code, output of 135 / 225 bytes |
| `phy_g_smooth` (new) + `phy_channel_estimator` | 3-bin moving average of the LTS channel estimate (≈ +2 dB at low SNR on every channel tested; a 9-bin window lost on echo > 2 us) |
| `phy_rx_top` | `WIN_DELAY` line (the detector declares up to 704 samples after the timing peak), header symbol (+1 window), `mode_q`, new status bits |
| `phy_rx_axis_top.v` | cfg `0x1C`: `MMSE` bit 0, `HDR_EN` bit 1, `MODE` bit 2 (fallback); cfg `0x28`: `FT_EN` bit 0, `SMOOTH` bit 1 (3-bin smoothing) |

Packet record header v3 (`phy_rx_pkt_out`): beat 4 bits `[23:20]` = `{header nsyms mismatch, header CRC ok, MODE_ID, dual-mode}`.

## Where the SNR gain comes from (ablation, see the report)

QPSK (−) → LDPC 1/2 (−) → soft LLR → MMSE + per-bin LLR weights → fine timing → CPE / SFO tracking → channel-estimate smoothing (3 bins). Each step is measured with
`SNR(PER = 1 %)` in `phy_sim/experiments/dualmode_study.py`.
